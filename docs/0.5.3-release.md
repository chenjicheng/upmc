# UPMC 0.5.3 release

Replace launch-triggered tray hiding with ordinary Windows taskbar minimization.
The setting reads `启动游戏后最小化`, defaults off, and retains existing explicit
opt-in values through the historical `hide_after_launch` settings key. The tray
dependency and its attribution entry are removed; other attributions remain.
See [taskbar behavior and implementation evidence](0.5.3-taskbar-behavior.md).

The package, workflow, artifact URL, and publisher target exactly `0.5.3`,
`v0.5.3`, the official `v0.5.3/updater.exe`, and `.upmc-release-0.5.3.json`.
Only an official-repository exact-tag push may publish. Branch/manual runs
remain build-only.

## Promotion contract

Both existing bridge feeds must match the schema-validated 0.5.2 release marker
`.upmc-release-0.5.2.json`. All descriptors retain exact schema, version, SHA,
digest, URL, and positive integer size validation before comparisons; boolean
and float sizes remain invalid. Missing markers, unknown/newer versions, and
inconsistent feeds fail closed. Matching current-release reruns are idempotent.

The validated frozen 0.4.8 initialization route remains available. Original
legacy descriptors, CNAME, unrelated files, and all old markers remain unchanged.
The predecessor fixture explicitly preserves both 0.5.1 and 0.5.2 markers.
Atomic tree construction, expected-HEAD leases, source identity checks, immutable
Release-byte verification, and guarded Pages activation remain in place.

## Acceptance evidence and limits

The native regression first rejected the old tray implementation. Native tests
then passed for shown/minimized state, continued event processing, restore, and
both close paths. Primary pixel acceptance also passed default launch,
taskbar minimization, repeated restore, full chrome/navigation/body/footer, and
the settings page after restore. No redraw or styling workaround was added.

The primary observed an AccessKit Windows 0.34 post-close UIA warning after the
interactive test had passed and exited with code 0: `ClientToScreen(...).unwrap()`
reported invalid HWND. The dependency and close guards were unchanged; automated
non-UIA native close tests had clean stderr. Read-only source triage supports an
upstream stale-window accessibility-query race, but no baseline reproduction
established its exact trigger. This caveat is retained; manual close output is
not represented as entirely clean.

Release-gate RED evidence includes the old exact-version rejection, followed by
the validated 0.5.2 predecessor being rejected by the old 0.5.1 rule after the
current-version gate changed. Logs are `target/release053-red.log`,
`target/release053-predecessor-red.log`, and `target/release053-green.log`.
All 44 publication tests passed after the gate and predecessor updates.
The implementation worktree's first two full Rust runs had different unchanged
timing-sensitive test failures; both focused reruns passed. The primary owns the
integrated serialized workspace gate, independent review, release build, CI,
publication, and public artifact/feed verification. This document does not claim
that 0.5.3 has been published.
