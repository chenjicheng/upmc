# UPMC 0.5.2 release gates

The release package, tag gate, artifact URL, and Pages marker target exactly
`0.5.2`, `v0.5.2`, the official `v0.5.2/updater.exe` asset, and
`.upmc-release-0.5.2.json`. Branch and manual workflow runs remain build-only.

This release includes the PCL window behavior described in
[0.5.1-window-behavior.md](0.5.1-window-behavior.md): successful launch keeps the
updater alive and visible by default, with an optional saved setting for hiding
to the Windows system tray.

## Pages promotion contract

The production predecessor is 0.5.1. Promotion requires both bridge feeds to
agree exactly with `.upmc-release-0.5.1.json`. That marker must have the exact
descriptor schema, version 0.5.1, a full lowercase commit SHA and SHA-256,
positive integer byte size, and the official 0.5.1 asset URL or approved proxy.
Missing markers, mismatched feeds or artifact metadata, unknown versions, newer
versions, and current-version feeds lacking their marker are rejected.

The existing frozen 0.4.8 bridge initialization route remains supported when
both bridge feeds match the frozen transition. Original `version.json`,
`dev/version.json`, `.upmc-legacy-transition.json`, `CNAME`, all historical
release markers, and unrelated Pages files are preserved. Only both bridge
feeds and the new release marker change together in one candidate Git tree.

Publication still validates the source tag/commit/channel, checks immutable
Release bytes against the actual CI artifact, and pushes with an expected-HEAD
lease. A matching 0.5.2 rerun is a no-op; it never rewinds a subsequent promotion.

## Local verification and remaining acceptance

Before implementing predecessor support, the version-gated suite reproduced
the real promotion failure: 37 passed and the validated 0.5.1 promotion was
rejected as an unknown/newer bridge release. The rejection occurred in the
publication guard, after source identity had been updated to 0.5.2.

After implementation, all 41 publication tests passed. A focused regression
also reproduced and fixed Python boolean/integer equality accepting an invalid
feed size; both predecessor promotion and current-release rerun validate each
feed's schema before comparison. Its final focused check passed separately.

Tests use temporary local Git repositories and non-executable artifact bytes;
GitHub requests are simulated. Evidence logs are `target/publication-red.log`,
`target/publication-predecessor-red.log`, and `target/publication-green.log` in
the implementation worktree; the type-boundary evidence is in
`target/publication-bool-red.log` and `target/publication-bool-green.log`.
Native desktop acceptance, integrated release
build/tests, independent release review, CI, publication, and public asset/feed
verification remain primary-agent release gates. This document does not claim
that 0.5.2 has been published.
