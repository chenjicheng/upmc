# UPMC 0.5.0

Based on stable 0.4.8 (`d5ff998`), not the independent 0.6 development branch.

The Slint interface replaces NWG while preserving the existing installation directory, bootstrap, packwiz, PCL, Xray, Discord DLL, self-update helper and channel contracts. The home page displays installed Minecraft/Fabric metadata, update progress, retryable errors and the PCL launch action. Settings persist UDP and stable/dev selection. The About page includes the official AboutSlint widget and bundled third-party copyright/license texts.

Jobs are serialized: updates revoke prior launch readiness, a failed launch keeps the UI open, and proxy failures do not revoke game readiness. Closing is deferred while a job is active. Proxy intent and failure status stay in the footer; transient proxy progress deliberately remains hidden, as requested. Rust workers send bounded events to the GUI thread; background panics and spawn failures become visible errors.

Switches respond optimistically without an intermediate connecting/stopping label or disabled-opacity flash. Proxy start failures revert to off with an error-details action; settings write failures restore persisted values. Long-running update/launch busy hints appear only after 300 ms; fast results and errors are applied directly. Guards still serialize work even when a transient disabled appearance is suppressed.

Proxy and settings errors are scoped to their control areas. Proxy failure shows an adjacent “未启用 · 查看原因” action without changing the main content; main-operation error details use reserved space and do not reposition Check Update. Unrelated successful operations do not erase the most recent failure details; retrying that operation or checking updates clears them.

During switch operations, further clicks update the displayed choice immediately and coalesce pending requests per control. Older completions cannot overwrite newer choices. Settings acknowledgement updates the cached choice and active channel/title without rereading an unrelated settings file. Update/launch transactions retain their operation guards. Full failure causes and relevant execution steps accumulate in one reusable error window; page-level markers contain no detailed causes. A failed worker creation restores the pre-operation proxy state, and offline game rechecks retain known running proxy state.

UDP is enabled by default for new installs and settings from older releases, including an explicit old `proxy_udp: false`. The proxy master opt-out is retained. Settings serialization records `udp_policy_revision: 1`, so a subsequent manual UDP opt-out survives restarts. Decoding legacy settings applies the migration in memory without requiring a startup disk write; every settings save persists the current policy revision. Automatic proxy restoration synchronizes existing proxy.txt files. Discord is restarted only if an installed proxy configuration changes, so the migrated UDP value also takes effect in the running process. Stop/write/restart failures propagate to the shared error window.

## Validation

- State tests first failed on missing update/launch gating; native view and persistence tests first failed on missing rendering and UDP persistence, then passed after implementation.
- Flicker regressions first failed on replacing the game status and primary label during proxy start. Fixed state/view tests also assert unchanged launch and proxy control positions.
- The workspace suite passes; existing ignored self-update tests remain explicit opt-in checks.
- `cargo test --locked -p upmc gui::tests::desktop_window_smoke -- --ignored --exact --nocapture` opens the actual native UI with an isolated temporary fixture. Update/proxy/launch effects are replaced only in this test, while settings use the real file persistence functions. Production has no mock mode.
- Independent review approved publication commit `9d52f03`; the primary inspected its guards and retained additional Release-byte, idempotence, missing-entry and race tests.
- Normal release builds do not enable Slint live preview. Development can use `SLINT_LIVE_PREVIEW=1` and `--features slint/live-preview`; Rust changes still require compilation.

## Publication

`.github/workflows/release-slint.yml` builds and tests exact tag `v0.5.0` using the existing `UPMC_SUB_URL` secret. The publisher verifies the remote tag and downloaded executable bytes before atomically promoting `bridge/version.json` and `bridge/dev/version.json` under a lease. The original `version.json`, `dev/version.json`, CNAME, legacy transition marker and unrelated Pages files remain unchanged. Existing release bytes are never overwritten.

This keeps old clients on the 0.4.8 first hop before they receive 0.5.0 through the bridge feeds. Live acceptance requires successful CI, an available Release asset and matching public bridge descriptor hash/size/build ID; local build success alone is insufficient.

The bundled notices were collected from the Windows Cargo dependency graph and upstream license files. Identical texts are stored once with SHA256 references. Source URLs identify additional upstream license texts where crate packages omitted them. Xray, PCL and downloaded Java/tools remain separate upstream distributions; this release does not redistribute their executable contents.
