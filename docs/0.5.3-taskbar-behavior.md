# Taskbar minimization after PCL launch

The optional setting is now `启动游戏后最小化`: after a successful PCL launch,
the updater minimizes to the Windows taskbar. Its native window stays shown and
the process remains alive. The default is off. Failed PCL launches do not
minimize the window.

The stored `hide_after_launch` key is retained for compatibility. An existing
explicit `true` now means minimize after launch; existing false and missing
values keep the updater in the foreground. The switch retains optimistic
feedback, serialized latest-intent handling, and rollback on persistence errors.

The updater no longer creates a notification-area tray icon, hides its main
window, or restores it by calling `show()`. Taskbar restoration uses Windows'
normal minimize/restore behavior. Native and custom close retain their existing
idle/busy behavior.

Native integration tests assert actual window visibility and minimized state,
continued event-loop activity, restoration, and both close paths. Those state
checks do not prove full-chrome pixel rendering. The primary agent must inspect
the restored home and settings pages using the actual taskbar before release.
