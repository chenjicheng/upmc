# Automated native window acceptance

Two ignored Rust integration tests drive the application's own callbacks from a
test-only timer. Run each test alone in its own process because the winit backend
owns a native event loop:

```text
cargo test -p upmc gui::tests::native_lifecycle_with_native_close -- --ignored --exact --nocapture
cargo test -p upmc gui::tests::native_lifecycle_with_custom_close -- --ignored --exact --nocapture
```

Each test uses the real Slint winit backend, embedded icon resource, tray-icon
builder, native window visibility, and production restoration method. Backend
work is restricted to an isolated temporary directory: update and PCL launch
return fixture outcomes; the preference is saved by the real settings handler.
Unexpected backend requests fail. No PCL or Discord process is launched, and no
desktop input, injected window messages, or accessibility automation is used.

The sequence verifies:

1. A successful launch keeps the default native window visible without a tray.
2. The hide switch responds immediately and persists before the next launch.
3. The next launch creates the real tray and hides the native window.
4. Three subsequent timer ticks prove the persistent loop remains alive hidden.
5. Production restoration shows the window; a subsequent minimize and restoration
   verifies its native minimized state becomes false.
6. The native close handler or the custom close callback quits the loop and the
   test returns successfully.

The production tray receiver's left-button-up branch calls the restoration
method exercised here. This fixture does not synthesize a notification-area
mouse click or native operating-system close event; the native-close test calls
the same close handler registered by the application.

An internal 15-second deadline reports the failing stage and shared errors. Local
acceptance also ran each executable under a 30-second process deadline. Both
native tests passed (native close 0.85 seconds; custom close 0.56 seconds). The
headless GUI suite passed 27 tests with the three explicit desktop tests ignored.
Evidence is in `target/native-close.stdout.log`, `target/custom-close.stdout.log`,
their corresponding stderr logs, and `target/native-lifecycle-headless.log`.

This is additional coverage of existing production behavior: no new runtime
behavior or production test mode was introduced, and no new behavioral defect
required a RED/GREEN implementation correction.
