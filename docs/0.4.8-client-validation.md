# Legacy 0.4.8 client validation

Worktree: `.release-0.4.8/agents/client`; baseline `ee1b98ce8e98df6799a42a394e75438b07c09cfd`.
All commands run here with this worktree's own default `target/`. The original
`discord-proxy-dll` and `force-proxy-dll` were built in release mode before the
first main-client test. No installed application or game directory was launched.

## Bridge discovery and version selection

Before implementing new behavior, eight behavioral tests were added to
`selfupdate_bridge_tests.rs`. The original inline build-ID decision was extracted
unchanged into a callable test seam; its version/channel arguments were initially
unused. This was a compiling seam, not an implemented SemVer policy.

`cargo test -p upmc bridge_tests -- --nocapture` against the original decision and
reader: **3 passed, 5 failed** (exit 101). Exact failures included:

```text
assertion failed: !required("0.4.7", REMOTE, Some(LOCAL), UpdateChannel::Dev)
assertion failed: !required("0.4.8", REMOTE, Some(LOCAL), UpdateChannel::Stable)
missing version accepted
left: "https://upmc.chenjicheng.cn/version.json"
right: "https://upmc.chenjicheng.cn/bridge/version.json"
accepted version: "v0.4.8"
```

After implementing required schema validation, the official Release/proxy URL
allowlist and SemVer precedence (including build-metadata equality), the same
command passed **8/8**. The old reader compatibility test still recognizes the
new commit and ignores added fields. A local dev build with no explicit build ID
does not replace itself solely for an equal-version remote build.

Raw command output is retained locally in `.validation/01-discovery-red.txt`,
`.validation/02-discovery-green.txt` and `.validation/03-discovery-regression.txt`.
These generated logs are not release inputs.

The bridge remains HTTPS-origin trusted; SHA256 and size are integrity checks,
not signatures. No native protocol, downloaded trust root, CAS, TUF or server
changes are included. The subsequent helper milestone and its validation are
recorded below when complete.

## Owned replacement and native-compatible health acknowledgement

Before replacing any helper implementation, five tests ran against the unchanged
legacy helper: `cargo test -p upmc helper_regression_tests -- --nocapture`.
All five failed behaviorally (exit 101): launch failure and non-PE staging
overwrote the previous executable; a zero copy budget mutated the destination;
the permanent `NotFound` error lost its type; 100 helper names produced only one
unique name in a single clock tick. Exact output: `.validation/04-helper-red.txt`.

The explicit channel restart test also failed with actual arguments `[]`,
expected `["--channel", "stable"]` (`.validation/05-channel-red.txt`). Its minimal
new command-construction seam initially returned the old bare command. The new
helper forwards the selected channel to both candidate and rollback launches;
omitted channel continues to use the persisted configuration on normal startup.

The audited `14eadd0` helper and health-ack implementation was adapted from the
read-only native checkout. Native manifest/CAS/TUF references and native-only
tests were removed. Existing audited tests were retained as regression coverage,
not relabeled as tests newly proven RED on the legacy interfaces. The new legacy
fixtures only gained an expected-identity argument when adapting to the repaired
helper; their preservation assertions stayed unchanged.

`cargo test -p upmc selfupdate -- --nocapture` passed **64 tests**, with one
subprocess-fixture test ignored in the top-level harness and explicitly invoked
by the mapped-helper test. Coverage includes real Windows mapped-process
ownership, competing OS file locks, atomic replacement, staging/installed digest
failure, candidate launch failure/early exit/timeout, stop-before-rollback,
termination failure forbidding rollback, rollback/relaunch failure, bounded
typed file retries and error chains, exact health acknowledgement bytes,
argument validation and cleanup under active ownership. The initial adaptation
had one missing-function compile error; it is recorded in `06-helper-green.txt`
as a compilation failure, not behavioral RED. Successful output is
`.validation/06b-helper-green.txt`.

A further helper boundary test demonstrated zero expected size reaching path
access (`07-size-argument-red.txt`); it now fails immediately as invalid metadata.
The startup acknowledgement uses the unchanged `UPMC_SELF_UPDATE_HEALTH_V1`
header, 64-hex challenge and `--self-update-health-ack` /
`--self-update-health-token` arguments accepted by native 0.6.0. A supervised
startup skips cleanup, and acknowledges only after a visible window exists.
