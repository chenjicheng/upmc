# Legacy 0.4.8 client validation

Worktree: `.release-0.4.8/agents/client`; baseline `ee1b98ce8e98df6799a42a394e75438b07c09cfd`.
All commands run here with this worktree's own default `target/`. The original
`discord-proxy-dll` and `force-proxy-dll` were built in release mode before the
first main-client test. No installed application or game directory was launched.

## Bridge discovery and version selection

Before implementing new behavior, eight behavioral tests were added to
`selfupdate_bridge_tests.rs`. The original inline build-ID decision was extracted
unchanged into a callable test seam; its version/channel arguments were initially
unused. This was a compiling seam, not an implemented SemVer policy.

`cargo test -p upmc bridge_tests -- --nocapture` against the original decision and
reader: **3 passed, 5 failed** (exit 101). Exact failures included:

```text
assertion failed: !required("0.4.7", REMOTE, Some(LOCAL), UpdateChannel::Dev)
assertion failed: !required("0.4.8", REMOTE, Some(LOCAL), UpdateChannel::Stable)
missing version accepted
left: "https://upmc.chenjicheng.cn/version.json"
right: "https://upmc.chenjicheng.cn/bridge/version.json"
accepted version: "v0.4.8"
```

After implementing required schema validation, the official Release/proxy URL
allowlist and SemVer precedence (including build-metadata equality), the same
command passed **8/8**. The old reader compatibility test still recognizes the
new commit and ignores added fields. A local dev build with no explicit build ID
does not replace itself solely for an equal-version remote build.

Raw command output is retained locally in `.validation/01-discovery-red.txt`,
`.validation/02-discovery-green.txt` and `.validation/03-discovery-regression.txt`.
These generated logs are not release inputs.

The bridge remains HTTPS-origin trusted; SHA256 and size are integrity checks,
not signatures. No native protocol, downloaded trust root, CAS, TUF or server
changes are included. The subsequent helper milestone and its validation are
recorded below when complete.
