# UPMC 0.5.4

This release retains the taskbar minimization behavior from 0.5.3 and includes
the following validation and release reliability changes:

- The HTTP timeout fixture now coordinates request acceptance and body delivery,
  requires an actual typed body timeout, and performs bounded cleanup. It no
  longer assumes a tiny global timeout guarantees an accepted request.
- Pull requests and main commits require **UPMC tests**. Before any automated
  publication, the exact merged commit must have successful canonical main
  validation, build, and CodeQL runs. Missing, failed, unfinished, or mismatched
  evidence blocks publication; see [the release gate contract](release-green-gate.md).
- GitHub validation responses are decoded explicitly as strict UTF-8, avoiding
  Windows system-code-page reader failures. Invalid UTF-8 remains an error.

The only release-policy edits are `package.version = "0.5.4"` and the explicit
predecessor `0.5.3` in `upmc/Cargo.toml`, with Cargo-generated lockfile sync.
Tags, download URLs, and marker names remain derived from that manifest. The
frozen 0.4.8 entrypoints and historical release markers are preserved.

Local validation covers the version-independent Python publication suite,
locked Cargo metadata, and a release build with freshly built embedded DLLs.
The local executable intentionally omits the subscription secret and is not a
distribution artifact. Official publication still requires independent review,
green PR checks, green checks for the exact merged main commit, the live release
gate, and the official CI artifact build. This document does not claim that
the release has been published.

Validation evidence: all 92 Python tests passed, and locked Cargo metadata
confirmed the manifest policy. Both the matched DLL build and updater release
build passed; the resulting PE file and product versions were verified as
0.5.4. The logs and metadata records are in
`target/release054-python.log`, `target/release054-metadata-locked.json`,
`target/release054-dll-build.log`, and `target/release054-build.log` in the
implementation worktree. Local artifact identity is recorded in
`target/release054-artifact-evidence.json` and is not an authorization to
distribute that validation-only executable.
